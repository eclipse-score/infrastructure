# Architecture Overview

Architecture pages provide the conceptual model that supports the operational documentation.

The primary navigation backbone is Infrastructure Areas. Architecture pages explain how those areas fit together, how tools map to them, and which concerns cut across multiple areas.

## What You Will Find Here

- [Infrastructure model](infrastructure-model.md): how the infrastructure is sliced into areas and connected to work packages
- [Tool landscape](tool-landscape.md): which tools are currently used and how they relate to areas
- [Cross-cutting concerns](cross-cutting-concerns.md): concerns such as traceability, reproducibility, controlled automation, and transparency

## How To Use Architecture Pages

- Use area pages for practical status and contribution entry points.
- Use architecture pages for shared vocabulary and system-level alignment.
- Use the [Infrastructure Development Map](../infrastructure-development-map.md) when planning work.

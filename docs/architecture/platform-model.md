# Platform Model

The platform model uses capabilities as the stable structure and work packages as the execution view.

## Model Layers

- capability layer: what the platform is
- work layer: what work exists and what remains
- guide layer: how to execute common tasks

## Why This Structure Is Used

- supports navigation by area and by task
- keeps architecture context stable as implementation details evolve
- helps contributors and managers use the same structural model

## Core References

- capability structure: [Capability Map](../start-here/capability-map.md)
- work map: [Work Breakdown Structure](../work-ahead/work-breakdown-structure.md)
- task guidance: [Guides Overview](../guides/overview.md)

## Boundaries

- this model does not imply fixed ownership mapping for every repository
- this model does not replace issue tracking or sprint planning
- this model is an organizing structure for infrastructure documentation
